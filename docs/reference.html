Cave View - Reference - v2 API

The following objects and methods are stable. Any other functions may change without warning.

The v2 API allows muliple independent viewers to be created and destroyed dynamically at run time.

focusStation( <reference>, <options> )

Select a station, and move the camera to centre the view on it.

A reference identifies a station or a survey section by name, either as a dotted path (entrance.pitch.3) or as an array of the individual path components ([ 'entrance', 'pitch', '3' ]). A dotted path is ambiguous when a name within it contains a dot of its own. A path that matches nothing is tried once more with its last two components rejoined into a single name, and only those two, so a name containing a dot is matched only when it is the last name of the path and contains a single dot. An array reference is matched one component at a time, and is the reliable form for names of this kind.

Returns a Promise, resolved with the Station object when the camera has finished moving. The Promise is rejected if no model is loaded, if the reference does not identify a station of the loaded model, or if the move is abandoned before it finishes - superseded by a later focus call, or cancelled by a selection made elsewhere.

Parameters
reference
string or ArrayThe name of the station.
options
ObjectAn object defined below (optional).

addLiveMarker( <id>, <reference>, <options> )

Display a marker at a station of the loaded model - a labelled dot drawn over the model, which an application adds, moves and removes while the model is displayed rather than loading a model to show it. Markers are displayed whatever the view settings are, and are drawn against the model like its own features: one placed at a station that the terrain covers is hidden by it as the station is.

The identifier names the marker for the calls below, and adding a marker with the identifier of one already displayed replaces it. The reference names the station the marker is placed at, in either of the forms focusStation() accepts.

A label may be a single string, or an Array of the strings its lines are. The lines are drawn one below the other, ranged left, with the first of them on the line of the dot: a label grows downwards as lines are added to it, so the dot stays where it is and whatever the marker is first called stays beside it. The block is set clear of the dot rather than starting on it, by a distance in the pixels the dot is drawn in, so it is beside the dot on a screen of any density. Whether the markers are labelled at all is the liveMarkerLabels property.

The text of a label is drawn smaller than the labels of the model are - a marker is labelled with a block of lines rather than with the single name a station is labelled with - and a translucent backing is drawn behind the whole block, so that a list of names can be read over the line work of the survey and over the markers of its stations. The size is the liveMarkerLabelSize property and the backing is the liveMarkerLabelBacking property; the colour and the opacity of the backing are the theme's (liveMarkers.labelBackground and liveMarkers.labelBackgroundOpacity). An application that wants the text alone, at the size the labels of the model are drawn at, sets the size to null and the backing to false. The label is drawn over the line work of the survey and over the markers of its stations, whatever it is drawn at, and under anything the application displays over the model; the dot is drawn against the model as before, and is hidden by the terrain where the station it stands at is.

A marker is pointed at over an area of the screen rather than where its dot is drawn: a disc of 32 pixels for a pointer that hovers and of 44 pixels for one that does not, which is the smallest target a finger reaches reliably. The label is pointed at over the area its text covers, and the backing drawn behind the text adds nothing to it: a pointer over the backing but not over the text reaches whatever is drawn behind them both. The disc is the same size however far the model is zoomed in or out, because the dot is drawn at the same size however far the model is zoomed, and it belongs to the markers alone: a station beside a marker is picked exactly as it was, and a pointer between the two reaches both.

A pointer that does not hover - a finger, and a pen used as one - reaches a marker by tapping it, which is what the larger of the two targets is offered to. A tap is told from the drag that turns the model by how far the pointer was taken from where it went down and by how long it was held, and is abandoned where a second pointer joins it, so one finger still orbits and two still zoom and pan: nothing is consumed and nothing is prevented. A marker crossed while the model is being turned is not reported, having been passed over rather than aimed at, and what a tap reveals stays revealed until something else is tapped - a pointer that does not hover ceases to exist as it is lifted.

A marker whose reference names no station of the loaded model, or that is added while no model is loaded, is held unresolved: it is drawn nowhere, it is reported as unresolved by getLiveMarkers(), and it is placed as soon as a model containing that station is loaded. A model that is cleared and loaded again therefore keeps its markers without the application adding them a second time.

Markers that resolve to the same station are collapsed into a single marker drawn in their place, labelled with the number of them or with what setLiveMarkerClusterLabel() says of them, and dispatching liveMarkerCluster rather than liveMarkerHover when it is pointed at. Markers at one station would otherwise write their labels over one another, which two of them is already enough to make unreadable. Markers are collapsed by the station they resolve to and not by how close together they happen to be drawn, so which of them are collapsed does not change as the model is turned, zoomed or resized. A marker alone at its station is drawn as described above, with its own label and sublabel.

Markers that set off between the same two stations at the same moment travel as one: they are drawn as a single marker for the whole of the move and not only at its ends, which is what a party moved together does. A marker travelling on its own - moved while the others of its station stay where they are, or moved at another moment - is drawn on its own while it travels, and is collapsed with whatever it finds at the station it arrives at.

Returns a live marker Object describing the marker added.

Parameters

moveLiveMarker( <id>, <reference>, <options> )

Move a marker to another station. The marker slides between the two positions where it is displayed at both, and appears at the new station where it is not - because it was unresolved, or because no model is loaded. A marker moved to a station the loaded model does not contain is held unresolved in turn: it is taken off the model rather than left at the station it was moved from. Options given replace those the marker was added with; those not given are left as they are.

Returns a live marker Object, or null if no marker of that name has been added.

clearLiveMarkers()

Remove every marker.

getLiveMarkers()

Returns an Array of live marker Objects, one for each marker added and not removed, in the order they were added - including those that are unresolved and so displayed nowhere, and those collapsed with other markers of their station. Collapsing is a matter of how the markers are drawn rather than of what the set holds, and each marker is reported with a resolved state of its own either way.

setLiveMarkerClusterLabel( <function> )

Set the function that labels a collapsed marker - the single marker drawn in place of the markers of one station. It is called with an Array of live marker Objects, one for each marker collapsed and in the order the markers were added, and returns the text to display. What the collapsed marker stands for is the application's to say: the viewer knows only how many markers there are.

The text may be a single string, or an Array of the strings its lines are, drawn one below the other as the label of a marker is. A collapsed marker commonly stands for a party, which has a name of its own and members of its own, and one line is not room enough to say both.

The number of markers collapsed is displayed where no function has been set, where the function returns null or undefined, and after a value that is not a function has been passed to remove one that was set. A function that throws is reported to the console and leaves the number of markers displayed: a collapsed marker that cannot be labelled as the application asked is still drawn, rather than the markers being taken off the model. The collapsed markers already displayed are built again to say what the new function says of them.

The function is called each time what is drawn is settled - as markers are added, moved and removed - and so is called more than once for a set of markers that has not changed. It is asked what a collapsed marker says rather than told, so that a marker says what the application now says of it without the application having to report the change.

Parameters
function
functionA function taking an Array of live marker Objects and returning a string.

dispose()

Free used memory including GPU and Javascript heap allocations.

Properties

liveMarkerLabels

Whether the markers added by addLiveMarker() are labelled. Setting it to false takes the labels off the screen and frees them - the text, and the backing drawn behind it - and setting it to true builds them again; the markers themselves are drawn and pointed at either way, so a screen that a party of markers has crowded can be cleared without the application taking its markers off the model and putting them back. Setting the property dispatches the change event, as the view settings do.

It is a property of the markers rather than one of the view settings, and so is not reset when a model is loaded: the markers outlive the model they are displayed on, and whether they are labelled outlives it with them. It is not reported by getView() and is not kept by saveView().

boolean default: true

liveMarkerLabelSize

The size the text of the labels is drawn at, in the unit the font sizes of the theme are given in. A marker is labelled with a block of lines - what it stands for, and a line for each of the several things that may be at one station - rather than with the single name a station is labelled with, so its text is drawn smaller than the labels of the model by default. A size of null is the size the labels of the model are drawn at, whatever the theme says that is (stations.default.fontsize, 18 where the theme says nothing), which is what an application that wants its markers labelled as the model is asks for.

Anything that is not a number greater than zero is refused, with a warning to the console, and the labels are left as they are: a boolean, a string of digits and undefined are refused rather than taken for the number they would convert to, and so is a size larger than the largest text the viewer draws. That largest one is set by the atlas a size of glyphs is held in - a fixed square of cells, one for each glyph, of which the fewer fit the larger the text is - and is 45 as the viewer stands. Setting the property dispatches the change event; the labels displayed are built again at the new size, and the markers themselves are untouched.

The size is in the pixels of the screen rather than in the pixels of the page, as every font size of the theme is: text of a given size is drawn in that many of the screen's own pixels, so on a screen of high pixel density it is sharper and smaller. The default is therefore not one number but 12 pixels of the page stated in the pixels of the screen - 12 * window.devicePixelRatio, and never more than the largest the viewer draws - so that a block of names is the same size on the page whatever it is displayed on. Twelve pixels of the screen on a telephone of 2.6 of them to the pixel of the page would be a block of four names 26 by 21 pixels of the page, with a cap height of six tenths of a millimetre, which is not a size a list of names can be read at; on such a screen the labels of the markers are therefore larger on the page than the labels of the model, which are given in the pixels of the screen by the theme. An application that wants a fixed number of the screen's pixels says so - viewer.liveMarkerLabelSize = 12 - and one that wants its markers labelled as the model is sets null.

number or null default: 12 * window.devicePixelRatio

liveMarkerLabelBacking

Whether a backing is drawn behind the text of each label. It covers the whole block of lines rather than each line, is sized to the text with a little room left around it, and follows the label as the model is turned, zoomed and resized: a list of names drawn over the line work of a survey, or over the cross hatching of a passage, is otherwise hard to read. Setting it to false draws the text alone.

The colour and the opacity of the backing are the theme's - liveMarkers.labelBackground and liveMarkers.labelBackgroundOpacity - as the other colours of the viewer are. The backing is drawn over the model and under the text of its own label, and is not pointed at: a pointer over the backing but not over the text reaches whatever is drawn behind them both. Setting the property dispatches the change event.

boolean default: true

Events

Listeners are registered with addEventListener( <type>, <listener> ) and removed with removeEventListener( <type>, <listener> ).

stationHover

Dispatched when the pointer comes to rest over a station, before the station name label is displayed. Stations are only tracked, and this event therefore only dispatched, when the stationLabelOver view setting is true. Hovering over any other part of the model dispatches no event.

A listener that displays its own information for the station sets the handled property of the event, which suppresses the station name label until another station is hovered over. The distance popup displayed while measuring between stations is not suppressed.

Properties
station
ObjectA Station object for the station under the pointer.
handled
booleanSet to true by a listener to suppress the built in station name label default: false.

liveMarkerHover

Dispatched when the pointer is moved onto a marker added by addLiveMarker(), or a pointer that does not hover is tapped on one, before the marker displays the second line of its own label. Markers are tracked whenever any of them is displayed, independently of the stationLabelOver view setting.

A listener that displays its own information for the marker sets the handled property of the event, which suppresses the sublabel until the pointer is moved onto the marker again. A marker added without a sublabel has nothing to display and looks the same either way. Nothing is displayed while the liveMarkerLabels property is false, however the event is handled.

The hover of a pointer that hovers ends when the pointer is moved off the marker, and when it is moved out of the model area altogether, so the sublabel of a marker is not left displayed behind a pointer that has gone elsewhere. What a tap reveals is left revealed until something else is tapped.

Properties
id
stringThe name the marker was added with.
payload
anyThe payload the marker was added with, untouched.
pointerType
stringThe kind of pointer the marker was revealed with, as the browser reports it.
handled
booleanSet to true by a listener to suppress the built in sublabel default: false.

liveMarkerCluster

Dispatched when the pointer is moved onto, or tapped on, a collapsed marker - the single marker drawn in place of the markers of one station - and reports the markers it stands for, so that an application can display what is at the station rather than how much of it there is.

This event stands in for liveMarkerHover for the markers collapsed: they are not drawn while their collapsed marker is, so there is nothing of them to point at. A marker alone at its station dispatches liveMarkerHover, unchanged.

A listener that displays the group itself sets the handled property of the event. A collapsed marker displays its label either way: unlike a marker drawn on its own it has no second line of its own to suppress, so an application that leaves the event unhandled sees the label it was collapsed with.

Properties
markers
ArrayA live marker Object for each marker collapsed, in the order the markers were added.
pointerType
stringThe kind of pointer the collapsed marker was revealed with, as the browser reports it.
handled
booleanSet to true by a listener to record that it has displayed the group itself default: false.
